# Stash — 素材ランチャー

グローバルホットキーで開く Spotlight 風オーバーレイから、登録した素材を絞り込んで
**他アプリへドラッグ&ドロップ** または **クリップボードにコピー** できる常駐ランチャー。

看板機能は **キャプション合成コピー**（`⌘⇧C`）。機器写真の下に型番の帯を付けた 1 枚の画像として
コピーできるので、メールや Teams へ「写真 + 型番」を貼る作業が一発で終わる。

## 動かす

```bash
pnpm install
pnpm start
```

`pnpm start` は `tauri dev`（Vite + Rust を同時に起動）。初回は Rust のビルドに数分かかる。

配布物を作るとき:

```bash
./scripts/release.sh --signed
```

`--signed` を外すと署名なしでビルドする（手元で試すだけならこれで十分）。
成果物は `src-tauri/target/release/bundle/` に出る。

## 配布の準備

### コード署名と公証（macOS）

未署名のままだと、他人の Mac では Gatekeeper に止められて素直に開けない。
Apple Developer Program（年 $99）に加入したうえで、次の環境変数を渡してビルドする。
値はシェル履歴に残さないこと（direnv や 1Password CLI 経由が安全）。

| 変数 | 中身 |
|---|---|
| `APPLE_SIGNING_IDENTITY` | `Developer ID Application: 名前 (TEAMID)`。`security find-identity -v -p codesigning` で確認 |
| `APPLE_ID` | Apple Developer アカウントのメールアドレス |
| `APPLE_PASSWORD` | appleid.apple.com で発行する **App 用パスワード**（Apple ID 本体のパスワードではない） |
| `APPLE_TEAM_ID` | 10 桁のチーム ID |

Hardened Runtime 用の entitlements は `src-tauri/entitlements.plist` に用意済み
（webview の JIT と、ユーザーが選んだファイルの読み書き）。

### 自動アップデート

署名鍵は **`~/.stash/updater.key`（リポジトリ外）**。公開鍵だけが `tauri.conf.json` に入っている。
**この鍵を失うと既存ユーザーへ更新を配れなくなる**ので必ずバックアップすること。

配信先は GitHub Releases。アプリは
`https://github.com/Changimari/Stash/releases/latest/download/latest.json` を見に行く。

リリースは 1 コマンド:

```bash
./scripts/publish.sh 0.1.1            # 署名なし
./scripts/publish.sh 0.1.1 --signed   # 署名 + 公証つき
```

3 ファイルの version 更新 → ビルド → `latest.json` 生成 → タグ → Release 作成までやる。
**`latest.json` を上げるまでアプリ内更新は配られない**ので、手でビルドだけしても更新は飛ばない。

今は Apple Silicon 向けのみ。Intel も配るなら `x86_64` 向けをビルドして
`publish.sh` の `platforms` に足す。

## 使い方

| 操作 | キー / 操作 |
|---|---|
| ランチャーを開閉 | `⌘⇧L`（設定で変更可） |
| Shelf を開く | メニューバーのアイコンから（ホットキーは既定では未割り当て） |
| 選んだ素材を Shelf に預ける | `⌘S` |
| 選択を移動 | `↑` `↓` `←` `→` / マウスを乗せる |
| **画像だけをコピー** | `⏎` または **クリック**（`⌘C` も可） |
| **画像 + 名前をコピー** | `⇧⏎` または **⇧クリック**（`⌘⇧C` も可） |
| カテゴリを切り替え | `⌘1`〜`⌘9`（`⌘0` で全件） |
| ライブラリ（管理画面）を開く | `⌘,` |
| 閉じる | `⎋` / 窓の外をクリック |

`⏎` / クリック側の動作は設定の「クリック / ⏎ の動作」で変えられる。
Shift 付きは常に「その逆のコピー」になるので、主に使う方を選べばよい。

名前を合成した画像は、既定では **背景が透過** で黒文字だけが画像の下に乗る。
白背景の資料やメールにそのまま貼ると、余計な帯が出ない。貼り先の背景色が読めないときは
設定で白／濃灰の塗りつぶしに切り替えられる。

文字の大きさは **画像に対する比率** で持つ（既定 3.2%、1〜20%）。絶対 px ではないので、
解像度がばらばらの素材でも見た目の比率が揃う。px の上下限クランプは意図的に入れていない
（入れると「大きい画像だけ頭打ち」という非相対的な挙動になるため）。

文字が画像の幅に収まらないときの扱いは 2 通り:

| | 挙動 | 出力の幅 |
|---|---|---|
| **折り返す**（既定） | 画像の幅に合わせて 2 行まで折り返し、超えたぶんは省略 | 元画像のまま |
| **はみ出す** | 文字サイズを優先し、**画像枠を超えて横に広げる**。折り返しも省略もしない。画像は中央に置かれる | 文字に合わせて広がる |

「はみ出す」では文字サイズの基準も画像の幅だけになる（縦で頭打ちにしない）。
小さいロゴに大きく型番を添えたいときはこちら。例: 600×200 のロゴ + 500% →
出力 988×425 で、文字が画像より明確に広くなる。

ドラッグアウトはタイルをそのまま掴んで他アプリへ落とすだけ。

## Shelf（ドラッグの一時置き場）

**ファイルを掴んだまま Shift を押す**と、カーソルの下に小さな 2 分割パネルが開く。

| 落とす先 | どうなる |
|---|---|
| 左「ライブラリ」 | 素材として正式に登録する |
| 右「Shelf」 | 預かるだけ。**そのまま一覧に伸びて残る** |

ホットキーではなく **ドラッグという文脈** で出すので、覚えるキーが増えず、
他アプリとキーを取り合うこともない。設定で切れる。

右に落とすとパネルが一覧の姿に伸びて、預けたものがそこに残る。
ヘッダーを掴めば好きな位置へ動かせる。閉じてもメニューバーから開き直せる。

### どうやって「ファイルをドラッグ中の Shift」だけを拾うか

3 つの条件が同時に成り立ったときだけ開く。どれも**現在の状態を問い合わせるだけ**の API で、
キー入力を監視するわけではないので**許可を求める必要がない**（60ms 間隔でポーリング）。

| 見るもの | API | 何のため |
|---|---|---|
| 左ボタンが押されているか | `CGEventSourceButtonState` | 掴んでいる最中か |
| Shift が押されているか | `CGEventSourceFlagsState` | 呼び出しの意思表示 |
| **ドラッグ中の中身がファイルか** | ドラッグ用ペーストボード | ただの Shift+クリックや文字の選択で開かないため |

3 つ目が肝。ボタンを押した瞬間のペーストボードの世代番号を控えておき、押している間に
それが増えて、かつ中身が `public.file-url` を含むときだけ「ファイルをドラッグ中」と判定する。
Stash 自身が始めたドラッグ（Shelf からの取り出し）は除外する。

Windows は 1・2 を `GetAsyncKeyState` で見る（3 は安く覗く手段が無いので判定しない）。

### なぜ要るのか

ドラッグは「掴んだまま目的地まで行く」必要があるが、目的地が別のデスクトップや
まだ開いていないアプリだとそれができない。Shelf はそこを分割する: **一旦預ける → 移動 → 出す**。

| 操作 | やり方 |
|---|---|
| 預ける | ドラッグ中 Shift → 右半分へ落とす / ランチャーで素材を選んで `⌘S` |
| **まとめて出す** | 「N 件をまとめて取り出す」を掴んで落とす（**1 回の操作で全部運べる**） |
| 1 件だけ出す | その行を掴んで落とす |
| 複製として出す（元を残す） | `⌥`（Option）を押しながら掴む |
| 取り除く | 行の × / ヘッダーのゴミ箱で全消去 |
| ライブラリに登録 | 下部のボタン。一時置きから正式な素材に昇格させる |
| 動かす | ヘッダーを掴んでドラッグ |

取り出しは既定で **移動**。ドロップが成功したら**元ファイルをゴミ箱へ送り**、Shelf からも消す。
`⌥` を押しながらなら複製になり、元ファイルも Shelf の項目もそのまま残る。

> OS へ渡すドラッグ操作自体は常に「複製」。一度「移動」を宣言したところ、Finder 以外の
> ほとんどのアプリ（Electron 製のものを含む）でドロップ自体を拒否された。macOS では
> 受け手が受け付ける操作を選ぶが、使っているプラグインは 1 種類しか宣言できず、
> 「移動」だけを出すと「複製」しか解さないアプリに届かない。
> だから移動の後片付け（元ファイルの始末）は Stash 側でやる。
>
> **削除ではなくゴミ箱へ送る。** `Dropped` は「受け手が受理した」までしか保証せず、
> 本当に保存されたかは分からない。取りこぼしても戻せる状態にしておく。
> 保管フォルダの中にある実体（ライブラリ管理下の素材）はゴミ箱にも送らない
> ——送るとライブラリが壊れるため。Shelf からは取り出したものとして消える。

オーバーレイと違い、**フォーカスを失っても消えない**（消えたら置き場にならない）。
× で閉じると預かり中のものは破棄され、最後の 1 件が無くなると自動的に畳む。
運搬中の物を置く場所であって、保管庫ではない。

ライブラリ（管理画面）はツールバーの並び順メニューから **追加日 / 名前 / 使用回数 /
最終使用 / ファイルサイズ** で並び替えられる（昇順・降順つき）。名前は数字を自然順で
比べるので、型番が `-1, -2, -10` の順に並ぶ。検索中も選んだ並び順を保つ（Finder と同じ流儀）。

カテゴリはサイドバーの **右クリック** から名前変更・サブカテゴリ追加・削除ができる。

### まとめて直す

複数選択すると右のパネルが一括操作に変わる。

- **キャプションを名前から一括で入れる**（空欄だけ / 全部を上書き）。ファイル名に型番が
  入っている素材を大量に取り込んだ直後に効く
- タグの一括追加
- カテゴリの一括付与・解除。「一部の素材にだけ付いている」状態は淡いアクセントで区別される

### ファイルを移動してしまったとき

素材は絶対パスへの参照なので、フォルダごと動かすとリンクが切れる。切れた素材があると
ライブラリ上部に帯が出るので、**移動先のフォルダを 1 つ指定すれば一括で貼り直せる**。
照合は内容ハッシュ優先・無ければファイル名なので、名前が変わっていても中身が同じなら追随する。
1 件だけ直したいときはインスペクタの「ファイルを探す…」から。

### 素材ファイルはどこにあるか

取り込んだ実ファイルは既定で **`~/Documents/Stash` へ移動**する。Stash が持つのは
絶対パスへの参照だけなので、ダウンロードフォルダを片付けた瞬間にライブラリが総崩れになる
——という事故を防ぐため。設定で挙動を選べる。

| | 動き |
|---|---|
| **移動**（既定） | 保管フォルダへ移す。取り込み元を消しても平気 |
| コピー | 複製を置き、原本も残す |
| そのまま | 元の場所を参照するだけ（従来どおり。原本を消すと切れる） |

保管フォルダは設定から変更でき、Finder で開ける。既に登録済みで外にあるものは
「まとめて整理」で後から移せる（サムネも焼き直す）。

管理画面を閉じてもアプリは常駐し続ける（macOS は Dock から降りてメニューバーに残る）。
完全に終了するときは設定の「終了」かメニューバーのメニューから。

## 設計上おさえておくところ

### 拡張ポイント（AV 特化版へ育てるための穴）

| 何を | どこ |
|---|---|
| 素材の任意フィールド（型番・メーカー・系統図種別…） | `assets.metadata`（JSON）。**列を増やさない**。`src/lib/types.ts` の `AssetMetadata` にコメントあり |
| カテゴリの初期値（汎用 ↔ AV 特化の差し替え） | `src/lib/presets.ts` の `ACTIVE_PRESET` 一行 |
| 素材種別の追加（将来の `text` スニペット） | `src/lib/types.ts` の `AssetType` と各所の分岐 |
| フリーミアム境界 | `src/lib/gating.ts` に集約。`ENFORCED` を true にしてライセンス層を挿す |
| 合成レイアウトの拡張（複数行・ラベル位置） | `src/lib/compose.ts` のみ。他に触る場所はない |
| 検索エンジンの差し替え（Fuse.js → FTS5 など） | `src/lib/search.ts` の `buildIndex` / `search` だけが外向き |
| プロダクト名 | `src/lib/brand.ts` と `src-tauri/tauri.conf.json` の `productName` |

### 決めごと

- **背景のすりガラスはネイティブ実装**（macOS: `NSVisualEffectView` / Windows: Mica・Acrylic）。
  CSS の `backdrop-filter` では偽装しない。非対応環境は CSS が不透明背景へフォールバックする。
- **合成コピーは必ず原寸から**。サムネイルからは合成しない。帯のサイズも文字サイズも
  画像の実寸に対する比率で決めているので、プレビュー用に縮小した画像で合成しても
  見た目の比率は原寸コピーと完全に一致する。
- **重い I/O はすべて Rust 側**。サムネ生成・SHA-256・フォルダ走査は `spawn_blocking` +
  rayon で回すので、数千件を取り込んでも UI は固まらない。
- **元ファイルは絶対に触らない**。Stash が持つのは絶対パスへの参照だけ。ライブラリからの
  削除でも元ファイルは残る。
- **サムネイルは `$APPDATA/thumbnails` にだけ置く**。`asset://` のスコープをそこに限定しているため。

### 開発時のメモ

- オーバーレイはフォーカスを失うと自動的に隠れるので、devtools で調べたいときは
  `STASH_KEEP_OVERLAY=1 pnpm start` で起動する。
- 見た目だけを詰めたいときは `pnpm dev` して `http://localhost:1428/__preview.html` を開く。
  Tauri のブリッジをモックした状態で両方の窓を素のブラウザに描くので、アプリを
  起動し直さずに CSS を往復できる（本番ビルドには含まれない）。
- DB は `$APPDATA/stash.db`。スキーマを変えるときは `src-tauri/src/db.rs` に
  マイグレーションを **追記**する（既存の version 1 は書き換えない）。

## Windows で確認すべきこと

開発は macOS で行っており、以下は **Windows 実機で未検証**。コード上の分岐は入れてあるので、
動かして確かめるべき点だけ挙げておく。

| 箇所 | 期待する挙動 / 懸念 |
|---|---|
| ドラッグアウト | `retreat_for_drag` は macOS では `NSApp.hide()` でアプリごと引っ込めるが、Windows には相当する仕組みが無く**ウィンドウを隠すだけ**。ドロップ先が覆われないかを確認する |
| クリップボード | ファイル参照は `CF_HDROP`。失敗したらパスのテキストコピーに落ちる（UI に理由が出る） |
| すりガラス | Windows 11 は Mica、届かなければ Acrylic、どちらも不可なら CSS で不透明にフォールバック |
| タイトルバー | `titleBarStyle: Overlay` は macOS 専用。Windows では通常のタイトルバーが出るので、サイドバー上部の余白を `data-platform` で出し分けている |
| 自動起動 | レジストリの Run キーに登録される |
| ホットキー | `CmdOrCtrl` は Ctrl に解決。表記も自動で `Ctrl` になる |

## 現状の制限
- クリップボードへのファイル参照コピーは OS 差が大きい。失敗時は絶対パスのテキストコピーへ
  自動で落ち、その旨を UI に出す。
- HEIC / RAW / PSD などは macOS では `sips` 経由で読める。Windows / Linux では非対応（プレースホルダ表示）。
- コード署名・公証は未設定。
